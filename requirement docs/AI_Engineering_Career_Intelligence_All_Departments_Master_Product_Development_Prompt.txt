2. PRODUCT VISION
============================================================

Build one unified platform for engineering colleges that can support ALL
engineering departments while allowing department-specific career intelligence.

The platform must answer four core questions for every student:

1. Where is the student now?
2. Which career roles align with the student's demonstrated skills and goals?
3. What skills are missing?
4. What should the student do next?

The platform must provide evidence-based assessment, explainable readiness
scoring, department-specific skill-gap analysis, personalized preparation plans,
reassessment, and institutional placement intelligence.

This is NOT a generic AI chatbot.

The product should be positioned as:

AI-POWERED ENGINEERING CAREER INTELLIGENCE PLATFORM

8. READINESS SCORE
============================================================

The readiness score must be deterministic, transparent, explainable, configurable,
and version-controlled.

Do NOT allow the LLM to directly decide the numerical readiness score.

Example conceptual structure:

Overall Readiness Score =
Weighted combination of:

- Aptitude
- Technical Skills
- Communication
- Problem Solving
- Resume
- Interview
- Projects
- Academic factors

Weights must be configurable.

The platform should support:

- Overall readiness score
- Category scores
- Department-specific score
- Career-role-specific score
- Company-specific eligibility
- Skill confidence
- Evidence supporting each score

IMPORTANT:

Readiness score is NOT a prediction of whether a student will get a job.

Never claim:

"Student has 85% chance of placement."

Instead use language such as:

"Current readiness level: Strong"
"Technical SQL competency requires improvement"
"Student meets configured eligibility criteria for this role"

============================================================
9. ELIGIBILITY VS READINESS
============================================================

Keep these concepts separate.

ELIGIBILITY:
Deterministic rules such as:

- CGPA >= configured value
- No active arrears
- Attendance >= configured value
- Department eligibility
- Graduation year
- Other company-defined criteria

READINESS:
Evidence-based competency assessment.

The system must never combine eligibility and readiness into one opaque score.

17. RAG + MCP ORCHESTRATION
============================================================

Example query:

"Am I ready for a Data Analyst role?"

Expected flow:

1. Authenticate user
2. Identify student
3. MCP retrieves current assessment/profile data
4. System identifies target role
5. RAG retrieves approved role requirements and resources
6. Deterministic engine calculates skill gaps
7. LLM explains the results
8. Recommendations are generated
9. Sources are cited
10. Audit event is recorded

The LLM should orchestrate explanations, not replace deterministic business logic.
